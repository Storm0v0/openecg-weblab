# QRS 时限与人工区间定量对照

协议版本：`coursework-v1`。本次新增逻辑只用 Python 标准库，从目录内的冻结 JSON 预测结果计算测量值，不调用模型、不改变滤波或检测参数、不修改原始信号和既有预测。当前正式演示为静态 HTML，没有文件导入、上传或在线模型运算。

## QRS 时限

每个预测 QRS 的时限为 `(end - start) * 1000` 毫秒。这是两个边界时间的差，不额外加一个采样间隔。以原有 250 Hz 时间坐标计算，采样步长为 4 毫秒；该步长不代表模型达到 4 毫秒测量精度。

逐区间列出起止时间、时限、唯一对应的 R 峰及统计状态。只有一个 R 峰落在该区间内、且该峰只对应一个 QRS 区间时，才建立配对；判断竞争时统计所有包含该峰的 QRS，不能忽略其中的多峰区间。缺失、多峰或共享歧义均留空，不用最近峰强行补齐。`rPeakAssociation` 分别输出 `unique`、`no-peak`、`multiple-peaks`、`shared-peak`。QRS 条目数与独立 R 峰数可能不同，QRS 时限统计不依赖 R 峰关联成功。

起点到达窗口首点，或终点到达末采样点的 QRS 标记为可能截断，仍列出但排除均值、中位数、最小值、最大值统计。无可纳入区间时输出 null，页面显示破折号。

## 人工标注对照

评价对象是 `groundTruth` 中已有完整起止边界的人工 P/QRS/T 区间。每条记录只针对当前十秒窗口。当前解析规则保留人工完整区间；这不表示数据库中的所有其他标注均被利用，尤其不是 T 峰或 T 终点的单点评估。

1. 各波形类别分别配对，按开始时间、结束时间、原索引排序。
2. 候选配对必须有正的时间重叠，且区间中心相差不超过 150 毫秒。
3. 用迭代动态规划进行保序一对一配对，先最大化配对数，再最小化起止边界绝对误差之和。不能重复利用预测或人工区间，平局按索引确定结果。迭代实现避免长序列超出 Python 递归层数。
4. 起点/终点有符号误差为 `预测 - 人工`，单位毫秒。MAE 为已配对区间绝对误差的平均值；同时输出偏差均值和时限 MAE。汇总基于未舍入的边界值计算，最终输出时保留三位小数，避免二次舍入。配对成功和边界达标分开统计。
5. 本项目采用的展示阈值：P 起点/终点各 50 毫秒；QRS 起点/终点各 40 毫秒；T 起点 50、终点 100 毫秒，等于阈值时计达标。
6. 人工区间配对率为 `配对数 / 人工区间数`。双边界达标率为 `起止均达标的配对数 / 人工区间数`；未配对人工区间留在分母内，计不达标。
7. 未配对预测不评分，不能当作假阳性。原因是人工覆盖不完整；不输出精确率、F1 或准确率。没有某类完整人工区间时，比例与误差均为 null，页面显示不可评价。

原有 QTDB sel100、sel103 示例没有提取到完整 T 波人工区间，不能推断它们没有 T 波、模型漏检或误检，也不能推广为整个 QTDB 没有 T 标注。新增记录是否可评价，以各自完整人工区间数为准。

## 解释范围

当前共二十条记录，LUDB 与 QTDB 各十条，每条展示十秒，仅用于示例对照。新增记录按官方记录存在性、导联及标注可用性确定，不按模型准确率选择。OpenECG 官方说明 v56c 训练使用了 LUDB、QTDB、ISP 等数据；本项目尚未逐条确认本地记录所属训练/验证划分。因此这些结果不是独立泛化测试，不能当作临床有效性或疾病诊断证据。

本协议的候选配对、统计分母与独立基准测试不同，不与 OpenECG README 中的基准 F1 直接比较。阈值用于本项目的展示对照，不构成临床诊断标准。当前也没有评价独立 R 峰检出性能。

官方项目来源：https://github.com/vitaldb/openecg

## 复现与输出

在 `03_网站与算法源码` 中分别执行：

```powershell
python scripts/test_coursework_analysis.py
python scripts/coursework_analysis.py
```

生成 `public/analysis/` 中每条记录对应的 JSON、QRS 逐区间表、人工对照逐区间表、对照汇总表。每份 JSON 记录源 JSON 的 SHA-256，可追踪到冻结输入。分析无需 NumPy、SciPy、WFDB 或模型依赖。

统一构建、检查和打包（2026-10-18 更新），从任意目录执行 `01_离线演示/release_static.py` 的完整路径即可。它在派生分析前和绑定核查时保护已有十四条预测、十四份分析及四十二个源文件的字节，随后运行算法测试、分析重生成、HTML 构建、模拟 DOM 测试，校验二十条记录、每库十条及原始输入/结果/内嵌数据绑定关系，同步部署首页，检查本地 HTTP，再生成确定性的五文件部署 ZIP 和 `静态发布清单_20261018.json`。它不会连接服务器或发布公网。

仅需重建离线 HTML 时，在 `01_离线演示` 中分别执行：

```powershell
python build_demo.py
node verify.cjs
```

构建时使用同一 Python 分析模块计算并内嵌结果。网页只读取预计算数据，浏览器不运行配对算法或模型。导出的心搏表增加 QRS 边界、时限和边缘状态；另提供 QRS 表、对照汇总、逐区间对照三个下载入口。

`test_coursework_analysis.py` 包含 16 项测试，另在测试中使用 80 组独立穷举对照和 1100 对区间验证配对。覆盖已知时限、截断、误差方向、缺失预测分母、无标注类别、重复预测、一对一最优配对、阈值边界、类别/重叠限制、R 峰共享/多峰歧义、二次舍入和输入保护。`verify.cjs` 验证目录内所有记录的表格、定位、筛选、自动加载、CSV/SVG 导出、切换清空及原有交互逻辑；它使用模拟 DOM，不代表实际浏览器或下载验收。

页面中所有汇总、CSV 导出均基于整段十秒记录。波形缩放、逐行定位及明细筛选只影响查看范围，页面显式标明这一点。SVG 导出记录当前原始/滤波状态、局部时间范围、预测/人工标注状态，移除悬停和拖动辅助元素，生成无需外部资源的矢量文件。

## 发布完善（2026-10-18）

静态页面另提供“导出结果说明 TXT”，整理当前记录、采样率与导联、固定处理步骤、QRS 汇总、人工区间对照、阈值和解释范围。它是结果说明草稿，不是临床报告或算法独立测试结论；全文仍以完整十秒记录为范围，不受当前缩放和明细筛选影响。

## 二十条演示与自动展示

统一目录为 `scripts/demo_catalog.py`，在此前每库七条的基础上各新增三条，共每库十条、二十条记录。原有十四条的预测 JSON、分析 JSON 和四十二个源文件逐字节保留；当前共六十个原始 WFDB 文件。数据来源、官方 SHA-256 与选窗依据记录在 `public/source_manifest.json`。页面打开时默认加载 LUDB 16；点击数据来源或选择下拉记录即自动加载，计数由内置记录计算，无需点击重新加载按钮。

新增预计算使用可选的 `prepare_demo.py --new-only`，验证并保留所有已有冻结 JSON 的字节，仅运行缺少的新记录。本次应只生成六条、保留十四条；本次模型适用的六个记录 ID、生成参数和保留记录哈希分别写入 `public/generation_manifest.json`，不将本次推理归属于原十四条。此前十四条的生成清单原字节保存在 `public/generation_history/generation_14_records_20261018.json`；原四条与实际模型环境的复现核查保存在 `public/model_replay_audit.json`，各类历史证据分开保留。

当目录内所有二十条均已存在，`--new-only` 只做快照和结构校验，不运行模型、不创建新生成清单，也不覆盖已有真实推理证据。统一发布使用交接目录中的十四条保护清单；独立 GitHub 包提供仅含项目内相对路径、大小和 SHA-256 的 `public/preservation_14_records_manifest.json`，核查同样的七十个受保护文件。
